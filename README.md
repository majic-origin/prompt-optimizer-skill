# prompt-optimizer

把口语化的需求重写成可直接执行的提示词，并在动手前处理信息缺口和幻觉风险。

一个 agent skill，适用于 DeepSeek Harness，Claude Code 与 Codex 也可直接使用。

## 解决什么问题

用户提交的请求通常缺三样东西：边界不清的目标、没说出口的约束、以及只有用户自己知道的素材。直接开做，产出的东西看着完整，实际偏离需求。

本 skill 的做法是先归类每个缺口，再决定动作。缺口的处理方式有三条出路，含糊过去不在其中。

| 类 | 判据 | 动作 |
|---|---|---|
| A 可澄清 | 用户掌握信息但未提供 | 追问，最多两轮 |
| B 可推断 | 存在行业合理默认 | 采用默认值并标注"默认采用 X，如不符请告知" |
| C 素材型 | 素材为用户私有、无法推断、追问亦不可得 | 不编造，改用 `{{占位符}}`，附替换说明 |

C 类是这套方法的核心。实物外形、私有数据、原始文件、个人经历、品牌资产都属于这一类：答案只存在于用户手上，常常不在文字里。问到底也拿不到，编一个出来则会让产出物失去价值。

## 效果示例

用户输入：

```text
给我写个能吸引人的小红书笔记，关于我家猫的，我想涨粉。
```

分类结果：账号定位与记忆点类型属 A 类，追问后闭合；猫的外形特征与照片属 C 类，追问无解。

产出形态随之降级为可复用模板：开头声明"本稿为模板，补 `{{猫的外形特征}}` 即可使用"，密度示例与真实素材分开写，附变量表供后续每篇替换。同时明确告知封面图对小红书流量的权重高于文案，并给出配图清单。

同类需求里常见的错误处理是替用户编一只猫，产出一篇读起来通顺、但用户发不出去的笔记。

## 安装

### DeepSeek Harness

本 skill 由 DSH 的 `dsh-skill-filesystem` 提供，它是一个本地发现 provider：扫描若干根目录，解析 `SKILL.md` 的 YAML frontmatter 生成目录条目，正文按需加载。

用户级安装，全局可用：

```powershell
.\tools\install.ps1
```

脚本把 `prompt-optimizer\` 复制到 `$env:DSH_HOME\skills\`，默认即 `~/.dsh/skills/`。

项目级安装，只对该项目生效：复制到 `<项目根>/.dsh/skills/`，项目根的判定依据是最近的 `.git` 祖先目录。

手动安装等价于一次目录复制：

```text
~/.dsh/skills/prompt-optimizer/SKILL.md
~/.dsh/skills/prompt-optimizer/references/*.md
```

发现机制的限制值得知道：provider 只扫描一层，只识别 `<root>/<name>/SKILL.md` 和 `<root>/<name>.md`，嵌套的 `SKILL.md` 不会被发现。所以 `references/` 里的文件不会污染目录，它们由 SKILL.md 在需要时按相对路径读取。

### Claude Code 与 Codex

frontmatter 字段兼容，直接复制目录即可：

```bash
cp -r prompt-optimizer ~/.claude/skills/
```

## 使用

显式调用：

```text
/prompt-optimizer
```

或者直接说出需求，skill 会自动加载：

```text
优化这个提示词：帮我把豆瓣上那部电影的短评都扒下来
```

默认只输出重构块，那是一份可复制的独立产物，拿去投喂任何模型都行。说"按这个执行"才会追加执行段。

## 六模块结构

重构产物固定为六个模块，顺序不变，无内容的模块写"未指定"，不硬凑。

```markdown
## 目标
一句话。动词开头，写明产出物和用途。

## 背景
角色设定、已有材料、任务场景。

## 关键约束
格式、长度、风格、语言、禁止项。

## 执行步骤
动作序列，不写原则。

## 输出格式
产出物的结构与形状。

## 验收标准
可检查的完成条件，每条都能用是或否回答。
```

## 文件结构

```text
prompt-optimizer/
├── SKILL.md                      主干：分流、缺口分类、六模块重构、防幻觉、自检
└── references/
    ├── gap-questions.md          按任务类型的问题库，含 A/B/C 归类与默认值
    ├── templates.md              五类场景的六模块成品骨架
    ├── guardrails.md             防幻觉约束原文，可整段复制进任何提示词
    └── examples.md               四组完整对照，含 C 类交付模板的演示
```

## 设计原则

缺口先分类再动作，不靠常识补决策项。交付形态、运行平台、技术栈、范围边界属于决策，缺了就问或挂占位符；细节参数才给默认值。

重构产物必须自包含。用户会把它复制到别处，或隔几天再拿回来用，所以关键决策只能出现在块内或 `{{待确认}}` 占位符里，写在块外的解释等于没写。

范围对齐量级。用户说"工具"时不写成"项目"，升级范围等于替用户追加工作量。

歧义列选项。原话有歧义的，把几种解读摆出来让用户选，不静默固化其中一种。
